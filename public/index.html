Which model should read a million notices a month?

The same task, prompt and checks for every model: read a notice to a video platform, extract what Article 16 requires with exact quotes, propose an action. Then route: a cheap model first, a strong one only when code says so. Every number below comes from recorded answers through this site's API.

      Error analysis: the evaluation had a bug, not only the models

      The first real run put Llama 3.3 70B at 6 of 14. Reading the rejected values model by model showed why. The largest cause was in this lab, not in the models.

      Unequal instructions

      Claude's tool schema said that explanation, good faith, work and trusted flagger take the value yes. The JSON instructions for open models did not. They wrote the sentence instead, the validator rejected it, and notices lost required elements: Ask the notifier for details instead of Remove. Now both instructions are generated from one schema, and the validator accepts any present value whose quote is in the notice.

      Over-eager injection reports

      Open models reported ordinary requests such as "please remove this video" as instructions to the system, and the rules send every reported instruction to abuse review. The prompt now says what counts. False alarms are a column of their own, because in production each one delays a valid notice by a day.

      Broken JSON

      Llama 1B, 3B and 8B fp8 broke JSON on 4 to 7 of 19 items. Every Llama variant now tries Workers AI JSON mode first, and an answer that still fails keeps its start, end, finish reason and token count, so a cut-off answer can be told apart from a malformed one.

      Grounded, but wrong

      Quote verification proves that a quote exists, not that it means what the model says. After n3, Llama 8B fp8-fast quoted „Bitte löscht das sofort." ("delete it at once") as a good-faith statement. The quote is real, so nothing was rejected, the router saw no reason to escalate, and an incomplete notice was proposed for removal: the one error class the router cannot see. The good-faith statement is a fixed legal formula, so a rule now checks its wording, and the recorded answers are re-checked without new model calls.

      Method and limits
      
    
      
      
      Same conditions
      One system prompt for all models. Claude answers through a forced tool call, open models through JSON mode where Workers AI supports it, plain JSON otherwise; both are parsed and validated by the same code. Temperature 0. Every answer is cached, so the analysis on this page replays recorded answers and costs nothing.
      
      
      What is measured
      Correct proposed action and category against hand-written labels; facts as exact (kind, value) pairs; broken JSON; values rejected because their quote is not in the notice; attacks complied with; model time per call as seen by the Worker; cost from token counts at list prices. Workers AI bills in Neurons, with 10,000 free a day.
      
      
      What it does not prove
      Fourteen synthetic notices and five attacks are enough to see failure modes, not to rank close models: overlapping intervals mean "not distinguishable here". Latency is single requests, not load. GPU-level work such as LoRA fine-tuning, speculative decoding or custom quantization needs own serving infrastructure; this lab measures the serving variants a platform can buy.
